# API contract — how it is defined and kept true

The API is **contract first**. There are two artefacts and a fixed order
between them.

| Artefact | Role | Who writes it |
| --- | --- | --- |
| `packages/contracts/src/**` (`@payana/contracts`) | **Source of truth.** TypeScript types for every request and response, closed enumerations, limits and regexes, and `ApiRoutes` — the complete path map with method, payloads and required access in its comments | People, by hand, first |
| `specs/api/openapi.yaml` | **Derived, published description** of the running API (OpenAPI 3.x) for people and tools that do not consume TypeScript | Generated by the API; committed |

`openapi.yaml` is never edited by hand.

## 1. Changing the API

1. **Contract** — edit `packages/contracts/src` (types, enums, constants,
   `ApiRoutes`). Additive within `/api/v1`; a breaking change needs `/api/v2`
   (ADR-0016). Bump the package version. Rebuild:
   `npm run contracts:build`.
2. **Spec** — update the owning feature spec under `specs/features/`
   (acceptance criteria, validation, authorisation) and add or adjust rows in
   `specs/traceability-matrix.md`. If the change closes a gap listed in a
   spec's "Gaps" section, strike it there.
3. **API** — implement controller, DTO (validation mirroring the contract's
   constants), use case, tests. Controllers take their paths from
   `ApiRoutes`; every handler declares its access (`public`, `user`, role or
   permission).
4. **Export** — regenerate the OpenAPI document:

   ```bash
   npm --prefix apps/api run openapi:export
   ```

   This boots the application without external side effects, builds the
   document from the decorated controllers and DTOs, and writes
   `specs/api/openapi.yaml`.
5. **Web** — use the new types through the typed API client in
   `apps/web/src/app/core/api`.
6. **Commit** contract, spec, code, tests and the regenerated
   `openapi.yaml` together.

## 2. What CI must enforce

The **drift** check is the minimum gate and is required from the first
pipeline. The other four are specified contract tests (F-18 IT-F18-09);
whether each is implemented is recorded in `specs/traceability-matrix.md`
against FR-OPS-005 and NFR-SEC-002 — do not assume they run until the matrix
says so.

| Check | Failure means |
| --- | --- |
| **Drift** — CI runs `openapi:export` and compares the result with the committed `specs/api/openapi.yaml` | A route or DTO changed without re-exporting. Run the export and commit |
| **Coverage** — every path built by `ApiRoutes` exists in the document with the listed method(s) | A contract route has no controller, or a controller uses a path not in `ApiRoutes` |
| **No extras** — the document contains no path that `ApiRoutes` does not define (documentation and health aside) | An endpoint was added outside the contract process |
| **Access** — every operation carries a security requirement or is explicitly public | A handler is missing its access declaration (default-deny, NFR-SEC-002) |
| **Errors** — every operation documents `ProblemDetails` for its 4xx/5xx responses | The error envelope is not declared |

A stale `openapi.yaml` fails the pipeline; it cannot be merged.

## 3. Conventions the document must reflect

| Topic | Rule |
| --- | --- |
| Base path | `API_PREFIX` = `/api/v1` |
| Media types | `application/json` for success; `application/problem+json` for errors (`ProblemDetails` with `code` ∈ `ErrorCode`) |
| Authentication | Bearer access token (`Authorization: Bearer …`); refresh via HttpOnly cookie on `/auth/refresh` (or body token for `X-Client-Platform: native`) |
| Idempotency | Operations marked `(idem)` in `ApiRoutes` require the `Idempotency-Key` header |
| Correlation | Every response has `x-request-id`; it equals `ProblemDetails.traceId` |
| Pagination | `page` (1-based), `pageSize` (default `DEFAULT_PAGE_SIZE`, max `MAX_PAGE_SIZE`) → `Paginated<T>` |
| Money | `Money { amountMinor, currency }`; request amounts end in `Minor` |
| Time | ISO-8601 UTC date-times; ISO dates for calendar days |
| Identifiers | UUIDs; slugs and codes where the contract says so |
| Enumerations | Closed string unions exactly as exported by the contract |
| Examples | Synthetic only — no real phone numbers, names or documents |

## 4. Reading the contract

- Start with `packages/contracts/src/routes.ts`. Each entry's comment gives
  `METHOD request -> response [access] (idem)`.
- Types are grouped by area: `common`, `identity`, `catalog`, `marketplace`,
  `bookings`, `commerce`, `engagement`, `config`, `admin`.
- Limits and patterns that validation must use are exported constants
  (for example `INDIAN_MOBILE_E164`, `MAX_PASSENGERS`,
  `REQUEST_TTL_MINUTES`, `UPLOAD_MAX_BYTES`, `GA4_MEASUREMENT_ID_PATTERN`).
  Feature specs quote them by name instead of repeating values.

## 5. Known gaps in the contract

Requirements that have **no operation or type yet** are listed in one place:
`specs/functional-requirements.md` §22, and again in the "Gaps" section of
each feature spec. They are implemented only after the contract is extended
through the process above — never by adding an undeclared endpoint.

## 6. Consumers

| Consumer | How it uses the contract |
| --- | --- |
| `apps/api` | DTO classes implement the contract interfaces; controllers use `ApiRoutes` |
| `apps/web` | Typed API client and stores import the types; validators use the constants |
| Future native app | Same package inside the Capacitor build (ADR-0007) |
| Third parties / QA tools | `specs/api/openapi.yaml`; Swagger UI at `/api/v1/docs` in non-production |
